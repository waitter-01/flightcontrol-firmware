# μC/OS-III 第七阶段：输出安全仲裁

## 阶段结果

算法候选值与硬件输出之间增加独立仲裁层：

1. 检查六电机和八舵机命令是否位于 `[0,1]`；
2. 保存最近请求值，便于离线回放和上机诊断；
3. 同时检查动力域、舵机域和硬件后端；
4. 任一条件不满足即清零“实际应用值”并累计拒绝次数；
5. 后端失败时锁存 `FC_SAFETY_FAULT_OUTPUT_BACKEND`；
6. 配电、继电器、Flash 写入和擦除提供明确接口，但固定返回安全锁定。

## 为什么不写入具体 PWM/GPIO

仓库没有完整 Vivado 工程和原理图确认记录，现有 PWM 自定义 IP 也没有可审查的寄存器协议。
在这种情况下猜测寄存器和有效电平会把“代码写完”变成不可控的硬件风险。因此当前完成的是
可审核的接口、仲裁和锁定实现，真正硬件后端必须作为上机阶段的独立小提交完成。

当前状态机没有 `ARMED` 状态，`fc_output_attach_backend()` 也固定拒绝绑定。即使姿态控制和
六旋翼混控产生非零命令，硬件输出仍为零。
