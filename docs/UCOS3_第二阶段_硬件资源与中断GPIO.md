# μC/OS-III 第二阶段：硬件资源、中断与安全 GPIO

## 阶段目标

本阶段建立后续驱动共同依赖的硬件资源表和统一平台接口，不迁移任何危险输出。资源表来自
当前 SDK 2019.1 HDF 生成的 `xparameters.h`，其中“映射已确认”只表示软件配置可以从现有
工程交叉验证，不代表原理图和实物已经验证。

## 新增模块

| 模块 | 作用 | 安全边界 |
|---|---|---|
| `bsp/board_resources` | 固化设备编号、地址、中断和风险等级 | 只读常量，不访问寄存器 |
| `platform/platform_irq` | 通过 Micrium BSP 注册、使能和禁用中断 | 不重新初始化 GIC |
| `drivers/gpio/gpio_input` | 初始化和读取 AXI GPIO 输入 | 整个通道强制设为输入 |

## 中断使用规则

1. μC/OS-III BSP 负责初始化 GIC，任何驱动不得调用 `XScuGic_CfgInitialize()`；
2. 驱动使用 `fc_irq_register()` 注册回调；
3. 中断回调只清状态、搬运固定长度数据并通知任务；
4. 中断中禁止等待、日志输出、动态内存和复杂协议解析；
5. 外设初始化失败时先禁用本外设中断，再向上返回统一错误码。

## 尚待实物确认的资源

当前只确认 HDF 中存在相关 IP，以下关系仍必须结合原理图和断负载测试确认：

- PS GPIO 的 MIO 编号与外部负载；
- 两个 CAN 控制器的收发器、终端和速率；
- 两组四通道 PL UART 的实际设备映射；
- 两个 AD7606 实例的量程、通道和采样时序；
- 三个 AXI IIC 控制器上的温度、电流传感器地址；
- LED、28 V、PMOS、继电器和 PWM 每一位对应的真实负载及有效电平。

因此本阶段不会初始化 LED、PMOS、继电器和 PWM 输出。
